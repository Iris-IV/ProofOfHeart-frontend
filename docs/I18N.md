# Internationalization (i18n) Guide

ProofOfHeart uses [next-intl](https://next-intl.dev) with the Next.js App Router. This
guide covers where translations live, how locale routing works, and how to add a new
language.

Currently supported locales: **`en`** (default) and **`es`**.

---

## How it fits together

| Concern                                                  | File                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Supported locales, default locale, locale cookie         | [`src/i18n/routing.ts`](../src/i18n/routing.ts)                                      |
| Loads the message catalog for the request locale         | [`src/i18n/request.ts`](../src/i18n/request.ts)                                      |
| Redirects and rewrites URLs to a locale prefix           | [`src/middleware.ts`](../src/middleware.ts)                                          |
| Validates `[locale]` and provides messages to the client | `src/app/[locale]/layout.tsx`                                                        |
| Translation catalogs                                     | [`messages/en.json`](../messages/en.json), [`messages/es.json`](../messages/es.json) |
| Build wiring                                             | `next.config.ts` (`createNextIntlPlugin("./src/i18n/request.ts")`)                   |

### URL structure

Every page lives under a locale prefix:

```
/en/causes          English
/es/causes          Spanish
```

The middleware (`src/middleware.ts`) uses `createIntlMiddleware(routing)` to resolve
the locale for incoming requests. The explicit locale choice is stored in a cookie
with `routing.localeCookie.maxAge` (`LOCALE_COOKIE_MAX_AGE`), so it persists across
browser sessions.

An unknown locale segment (for example `/fr/causes`) returns a 404. The `[locale]`
layout checks the segment against `routing.locales` and calls `notFound()`.

## Message catalogs

Catalogs are flat JSON files grouped by feature namespace:

```json
{
  "Web3Help": {
    "stroopsTitle": "What's a stroop?",
    "stroopsBody": "A stroop is the smallest unit of XLM: 1 XLM = {stroopsPerXlm} stroops."
  }
}
```

Use the namespace in `useTranslations` and the key in `t()`:

```tsx
"use client";

import { useTranslations } from "next-intl";

export function StroopsHelp() {
  const t = useTranslations("Web3Help");

  return (
    <div>
      <h3>{t("stroopsTitle")}</h3>
      <p>{t("stroopsBody", { stroopsPerXlm: "10,000,000" })}</p>
    </div>
  );
}
```

### Rules

- **Keep the key sets identical** in `en.json` and `es.json`. Every key added to one
  file must be added to the other, because a missing key falls back to the raw key
  string shown on screen.
- **Use ICU placeholders** (`{name}`) for values. Do not concatenate translated strings.
- **Keep catalogs valid JSON.** A syntax error in either file stops the app from
  loading messages for that locale. Check with:

  ```bash
  node -e 'for (const f of ["en","es"]) { JSON.parse(require("fs").readFileSync(`messages/${f}.json`,"utf8")); console.log(f, "ok") }'
  ```

- **Format numbers and dates with the locale.** Use `useLocale()` with
  `Intl.NumberFormat` or the helpers in `src/lib/formatters.ts`, as
  `DeadlineCountdown` does.

### Checking for unused keys

```bash
npm run i18n:check
```

The script lists keys in `en.json` that never appear in `src/**/*.{ts,tsx}`. Keys
starting with `step_` are ignored because they are built dynamically. Run it before
you remove a key from the catalog.

## Using locales in code

- **Client components:** `useLocale()` and `useTranslations()` from `next-intl`.
- **Server components and route handlers:** `getTranslations()` and `getLocale()`
  from `next-intl/server`.
- **Navigation:** import `Link`, `useRouter` and `usePathname` from
  `@/i18n/routing`, not from `next/link` or `next/navigation`. These wrappers add
  the locale prefix.

## Adding a new language

Example: adding French (`fr`).

1. **Register the locale** in `src/i18n/routing.ts`:

   ```ts
   locales: ["en", "es", "fr"],
   ```

2. **Create the catalog** at `messages/fr.json`. Copy `messages/en.json` and translate
   every value. The key set must match `en.json` exactly.

3. **Update hardcoded locale maps.** These do not read `routing.locales`:
   - `src/lib/siteMetadata.ts`: the hreflang `alternates.languages` maps (for `en`
     and `es`, plus `x-default`), and the `openGraph.locale` mapping
     (`es` → `es_ES`, otherwise `en_US`).
   - See [`HREFLANG_ALTERNATES.md`](HREFLANG_ALTERNATES.md) for the full hreflang
     behavior.

4. **Check the locale-aware code paths:**
   - `src/app/sitemap.ts` iterates `routing.locales`, so it picks up the new locale
     automatically.
   - `src/app/[locale]/causes/[id]/opengraph-image.tsx` receives the locale from the
     route. Check that its text renders correctly in the new language.

5. **Verify:**

   ```bash
   npm run i18n:check
   npm run typecheck
   npm test
   npm run dev   # then open /fr/causes and check that the page renders
   ```

Locale codes must be BCP 47 tags (`fr`, `pt-BR`). A region-specific tag such as
`pt-BR` also needs the matching `openGraph.locale` value (`pt_BR`).

## Troubleshooting

| Symptom                                                   | Likely cause                                                                            |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Raw keys such as `Web3Help.stroopsTitle` appear on screen | The key is missing from the active locale's catalog, or the catalog failed to parse.    |
| The whole page 404s for one locale                        | The locale is not in `routing.locales`, or the `[locale]` segment is misspelled.        |
| The language switch does not persist                      | The locale cookie was blocked. See `writeLocalePreference` in `src/lib/preferences.ts`. |
| `npm run build` fails on `messages/*.json`                | Invalid JSON. Run the validation command above.                                         |
